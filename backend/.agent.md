# ENGINEERING PRINCIPLES

Follow these principles at all times.

### Clean Architecture

Maintain strict layer separation.

```
API

↓

Services

↓

Repositories

↓

Database
```

Never violate this architecture.

---

### Single Responsibility Principle

Every class should have one responsibility.

Avoid "God classes."

---

### Repository Pattern

Repositories only perform persistence.

Repositories never contain business logic.

Repositories never call external APIs.

---

### Service Layer

Services own business logic.

Business rules must never appear in:

* Routes
* Repositories
* Models

---

### API Routes

Routes must remain thin.

Routes should only:

* Authenticate
* Validate requests
* Call services
* Format responses

Nothing else.

---

### Dependency Injection

Continue using dependency injection throughout the project.

Do not instantiate repositories or services directly inside routes.

---

### Scalability

Assume LearnOS will eventually support:

* Millions of users
* Thousands of concurrent requests
* Multiple content providers
* Background workers
* AI processing pipelines

Design accordingly.

---

### Extensibility

Whenever implementing a feature ask:

> "Will this architecture still make sense two years from now?"

Avoid shortcuts that make future development harder.

---

### Production Readiness

Write code that is:

* Readable
* Typed
* Tested
* Documented
* Modular
* Maintainable

Never sacrifice quality for speed.
